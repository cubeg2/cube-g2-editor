# Module replacement roles
#
# Why this file exists: a patch written years ago on the original hardware editor
# should keep working here, on current Apple Silicon machines. Swapping one module
# for a relative of it has to move the cables and the knob values to the places a
# user expects, or the patch quietly falls apart on the first edit.
#
# A role is one thing a module can do that survives being swapped for another
# module of the same family: a socket, a knob, or an output. When two modules
# in a family both fill a role, a cable or a knob value moves across on a swap.
#
# Written in module and port names on purpose - the names are what a user sees
# on the panel, and what makes an entry checkable against a running editor.
# Tools/generate_module_replacement_db.py turns this file into Swift; it reads
# port numbers from Sources/G2Core/ModuleDatabase.swift and never from anywhere
# else, so a rename or a reordered port is caught here rather than silently
# mapping a cable to the wrong socket.
#
# Syntax
#   family <name>           starts a family; every member may replace every other
#   members <Short> ...     module short names, in the order the menu offers them
#   knob <role>: M.Knob ... knob values that move together
#   in <role>: M.Socket ... input sockets; +Knob attaches a knob that travels
#                           with the cable (a channel level following its input)
#   out <role>: M.Socket .. output sockets
#
# A role may name the same module twice; that is how a mono pair folds into one
# stereo channel. Order matters only in those roles, so entries stay in order.
